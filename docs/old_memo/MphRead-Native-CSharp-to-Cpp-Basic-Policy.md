# C# → C++ 完全再現 基本方針

この文書は実装順や個別ファイルの監査結果ではなく、`src/MphRead` から
`src/MphRead.Native` へ移植するときの共通ルールだけを定める。

## 1. 仕様の唯一性

- 対象の完全な C# ファイルを唯一の仕様とする。
- 既存の C++ 実装、ビルドが通ること、推測した設計を正解扱いしない。
- C# に存在しない挙動、設定、ポリシー、フォールバック、最適化を C++ 側へ追加しない。
- 1つの C# ファイルを、対応する C++ の `.hpp` / `.cpp` ペアとしてファイル単位で再現する。

## 2. 再現する観測可能な意味

公開・internal 相当 API、型、継承、static 状態、既定値、null 相当の扱い、境界条件、
例外・失敗時の挙動、時刻・フレーム単位、フラグ、入力、状態遷移、メッセージ、
コレクションの順序、乱数・音声・描画などの副作用を C# と一致させる。

プログラム言語の差による置換（プロパティを getter/setter にする、参照型を対応する
所有・非所有参照で表す、標準コンテナへ写像する等）は許可するが、観測可能な意味を
変えてはならない。null、所有権、評価順、符号、整数幅、浮動小数点の単位を暗黙に
変更しない。

## 3. ファイル配置とヘッダ

- C++ の相対ディレクトリ階層は C# 側の相対階層に合わせる。
- `.hpp` は原則として対応する `.cpp` と同じ機能ディレクトリに置く。
- `include` へ一括配置して、どの C# ファイルの対応物か分からなくなる構成にしない。
- 共有宣言を変更する必要がある場合でも、既存の宣言所有ファイルへの最小の意味中立な
  変更に限定し、対象ファイル外の設計を広げない。

## 4. C++ 独自実装の禁止

次の目的で C++ 側に独自の意味を追加しない。

- C# にない API、状態、キャッシュ、スレッド、ロック、リトライ、ログ、フォールバック
- 正規表現・ヒューリスティック・近似による仕様の置換
- ビルドを通すためだけの shim、ダミー値、無条件の early return
- 実装順や既存の呼び出し側に合わせた仕様の改変

プラットフォーム差を埋める薄いアダプタだけは許可する。ただし、アダプタは C# にない
意味を公開せず、入力・出力・失敗の観測結果を増やさない。

## 5. 監査・検証

各ファイルは、完全な C# ソース、対応する `.hpp`、対応する `.cpp`、既存の直接呼び出しを
突き合わせてから変更する。コンパイラエラーは不一致の発見材料であって、C++ 側の独自
仕様を正当化する根拠ではない。

検証結果は次を分けて記録する。

- ソース静的監査・差分確認
- 対象コンパイル／ローカルテスト
- 実行時・実機・実 ROM 検証
- GitHub Actions の exact commit CI

実行していない検証を完了扱いにしない。変更が不要なら、理由と確認範囲を明記した
verified no-op とする。

## 6. Git 配信

- 編集直前に対象ブランチの最新 SHA を確認し、並行コミットを保持する。
- 変更対象だけを通常の commit/push で配信し、force-push は行わない。
- 配信後に親 SHA、現在のブランチ SHA、変更パス、各ファイルの blob SHA、差分量、
  exact-SHA CI の run ID と状態を確認する。
- push 成功はビルド・テスト・実行時検証の成功を意味しないため、両者を別々に報告する。
