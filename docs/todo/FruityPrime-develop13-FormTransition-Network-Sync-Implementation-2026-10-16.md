## 追補：Alt攻撃と形態の時刻合わせ（2026-10-16 夜）

`tools/test-session` の報告（トレースが通常フォームのまま変形攻撃）を受けて、
観測側のログを追った。原因は、**1体のレプリカに時計が2つあったこと**だった。

- 攻撃押下は中継インテントで届く（最新の権威時刻）。
- 形態はプレイアウト時計の読み点（最新から2〜8フレーム遅れ、到着が固まるとさらに遅れる）で表示していた。
- そのため押下が届いた時点のレプリカは変形クリップの途中にあり、ネイティブの
  `!IsMorphing()` 判定で攻撃が捨てられていた。スクリプトで全種のAlt攻撃を
  出させた250ms走行では、観測側の攻撃描画が**0件**だった。

対応（すべて `Mods/` 配下。`Entities/` はテスト用 friend 1行のみ）:

| 変更 | 内容 |
|---|---|
| 形態の読み時刻 | `NetSmoothing::FormFrame`。1ステップごとに1進み、最新スナップショットを越えず、2フレーム（`FormClockSlack`）より遅れない形態専用の時計。姿勢（位置）の読み点とは切り離した。描画間は `FormFrame(phase)` |
| 攻撃押下時の形態確定 | Alt攻撃の押下と、オーナーのAlt形態報告が届いたら、既存のボム用回復 `PlayerFormReplication::AdvanceForAltFormAction` を `complete` で呼び、表示中のクリップをそのフレームで完了させる（保持・遅延はしない）。追いつく前のサンプルによる巻き戻しは `FormPresentationPolicy::AltCommitHolds` が止める。止めるのは、Alt確定またはUnmorphのサンプルが来るまで（上限120フレーム） |
| Vhoscytheの溜め | `RemoteAltAttackClock`。権威を含むすべてのリモートコピーで、起動カウントをオーナーのフレームで数える。押下フレームは「インテントのフレーム − 押下経過」、現在は「インテントのフレーム ＋ そのフレームを初めて適用してからのステップ数」。到着時刻ではなく初適用から数えるのは、専用サーバーとクライアントで到着経過が1フレームずれるため。プロトコル変更なし |
| ハーネス | `NetTestScript` の押しっぱなしが毎フレーム新規押下になっていた（メインプレイヤーのバインドが毎フレームキーボードから詰め直されるため）のを修正。`FormBombCycle` のノクサス周期を360フレームに延長 |

チャージとヒットの扱い:

- ビームのチャージとボール突進の威力は、従来どおり `IntentPacket.ChargeLevel` / `BoostDamage` で送る。
- 押しっぱなしは毎インテントの状態ビットなので、ラグや欠損で「離した」扱いにはならない。
  インテントが30フレーム途切れても保持されることをチェック済み。
- 自分のVhoscytheのヒットは即時予測され、NoBeamのヒットクレームとして送られる。
  権威は自分のコピーの判定を捨て、クレームを近接半径（4ユニット）で検証して適用する。

### 残る境界

- スクリプト走行の「形態不一致」は合計71フレーム、最長4フレーム（最初の修正版では456フレーム・最長35）。
  内容はすべて「攻撃押下でAlt確定済みのレプリカ」と「最新スナップショットがまだ変形末尾（進行度14〜15/15）」の差。

- クレームの検証は被害者の位置だけで、攻撃側の起動状態は見ない（不正対策としては未対応）。

## 実装

- `ServerFormTransitionChannel` が、サーバーのシミュレーション後に発行される
  スナップショットと実際のクリップを観測する。`FormTransitionAuthorityTracker` は
  成立した変形にだけ `StartFrame` とライフ内 ID を割り当てる。
  `TrySwitchForms` の受理条件は複製していない。拒否は開始イベントにせず、
  元のスナップショット修復・owner 予測修復を維持する。
- プロトコル34、`PacketType::FormTransition = 43`。別パケットなので
  `PlayerState::Size = 140` と既存アイテム同期の予算は変わらない。
  ヘッダー15バイト、1人26バイト、8人でも型バイト込み224バイト。
  match/epoch/slot/generation/life/ID/start と、観測フレーム、ネイティブ
  30 Hz クリップのアンカー・フレーム数・停止状態・終了状態を送る。
- 開始・停止・終了時は即時、通常は3ティックごとに最新レコードを再送する。
  終了済みレコードも次の遷移またはライフ変更までチェックポイントとして再送し、
  途中参加時には最新スナップショットと一緒に送る。ACK 依存の一発送信ではない。
- Codec は長さ、人数、重複slot、ゼロID、不正な方向・状態・フラグ、時刻関係、
  clip 範囲、完了方向と最終フォームの一致を検査する。受信は既存のホスト認証経路に
  限定し、match/epoch/generation/life と生存・観戦状態を照合する。
  ID は16ビットの半周比較、0を予約し、周回後は1。新IDによる開始時刻の後退も拒否する。
- `FormTransitionTimeline` は1slot64観測の固定容量履歴。重複と旧IDを抑止し、
  終了通知の後に遅れた開始が来ても現在の時刻で再開しない。
  死亡・観戦・新ライフ・slot再使用・部屋・ストリーム境界で表示履歴を破棄する。
  破棄後の同じ終了チェックポイントの受信は、開始や効果音を再実行しない。
- （初版）`NetSmoothing::PresentationFrame` を位置の `SampleAhead` とフォーム描画が共有していた。
  **追補で変更**: 形態は `NetSmoothing::FormFrame`（最新の権威フレーム、形態専用の時計）で読む。
  指示書 Phase D.1 の「位置・ボムと同じ readFrame」は、Alt攻撃の押下と形態の時刻が
  ずれて攻撃が通常フォームに見える／消える原因だったため、ユーザーの指示
  （形態の遅延表示は不可、完全同期を目指す）で置き換えた。最新スナップショットを
  超えないという制約は維持している。
  形態ビットと安定形態への確定は従来のスナップショットが担当し、イベントから推測しない。
  イベントが欠けたときは4ビット進行度と既存の修復処理へフォールバックする。
- `PlayerFormPresentation` と `AnimationBlend::FrameOverride` は表示用の小数位相を
  ネイティブの node 曲線へ渡す。アニメーションフレームや flags を描画で書き換えず、
  node行列も既存の描画スコープでシミュレーション用の値へ戻す。
  ローカル入力予測・当たり判定・攻撃・Weavel砲台とHPの所有権は維持する。
- `-noformevents` は旧スナップショット進行度との比較用。
  `-nointerp` は従来の即時入力・ネイティブ再生を維持する。
- デモは同じパケットと権威フレーム時計を記録・再注入する。
  プロトコル33のgoldenを変更せず保存し、34のgoldenを追加した。
  33のクライアント・デモは既存のバージョン検査で拒否する。
- 診断専用の `-formtrace` で `[form-request]`、`[form-event]`、`[form-sample]` が要求、権威結果、
  共通readFrameと表示位相を対応付ける。
  `Entities/` の差分は要求診断と描画スコープの薄い呼び出しだけ。
  `Formats/` と `Metadata/` に新しい判断処理は置いていない。
